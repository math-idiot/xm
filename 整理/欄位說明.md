# 整理/ 統一格式說明(草稿,待確認)

每個活動一個資料夾,固定兩個檔:`活動.json`(文件)+ `獎勵.csv`(獎勵表,由 JSON 的階段/額外獎勵/排行獎勵統一產生)。
原圖排版的表格保留在 `原稿/批次N_csv/`,整理區不再重複放。
`00_總覽與規則/` 放跨活動的總覽、每週輪替、事件上限。`99_養成參考/` 放養成參考,拆成 突破 / 覺醒 / 心途 / 升級 四組,各一個 json + csv(裝備共鳴搬到 `91_養成/裝備`);突破與心途再依 N/R/SR/SSR/UR 分塊,每階素材後面都有「累計」欄(從 1 階加到該階的已用量)。`目錄.json` 是所有活動的索引。

## 活動.json 前半段(活動基本資料)

| 欄位 | 說明 | 範例 |
|---|---|---|
| 名稱 | 活動名稱 | 蘭台問心 |
| 別名 | 其他叫法 | ["杏林之星"] |
| 系列 / 輪替版本 | 同一活動有多個版本時,標出系列名與所有版本 | 曲水流觴 / ["幸運卡包","紅卡包"] |
| 分類 | 積分活動 / 材料收集 / 排行活動 | 積分活動 |
| 類型 | 個人積分 / 排名積分 / 個人收集 / 個人排行 | 個人積分 |
| 時長 | 活動期間(圖片沒寫的為 null) | 5天 |
| 結算 | 結算方式/時間 | 每日22:00結算 |
| 事件積分 | 類型=固定(固定事件倍數,事件清單列在「事件」)/ 隨機(隨機事件,無倍數)/ 依階段(各階段自有計分途徑,如杏林春魁)/ null(待確認);每個活動都有此欄 | {"類型":"固定","事件":[{"事件":"蘭台閱卷","積分":5},…],"備註":null} |
| 需求單位 | 階段需求的計量單位 | 積分 / 珍珠 / 避水珠 / 夢絲 / 藥材 / 領取分 |
| 階段數 | 階段總數(自動計算) | 10 |
| 全拿總需求 | 全部領完需要的累積數 | 1370 |
| 上榜門檻 | 排行榜要上榜的最低積分(杏林春魁:階段600、總榜10000) | {"階段(每日)":600} |
| 設定表階段 | 杏林春魁每個階段(每天)的積分來源,直接取自設定表 | — |
| 輪替版本事件積分 | 同一個活動的輪替版本各自的事件積分(遊園爭霸 / 杏林之星不同) | — |
| 全部領完總獎勵 | 把所有階段獎勵加總(取自遊戲設定表) | [{"道具":"行動力","數量":1310}] |
| 獎勵種類 | 主要獎勵類別(取自每日活動總覽) | ["貼紙包","行動力","升星石"] |
| 是否補發獎勵 | 是 / 否 / 僅最終大獎補發;未經遊戲內確認一律 null,並在備註附上每日活動總覽的參考值 | null |
| 獎勵順序隨機 | true = 獎勵與階段不綁定(隨機發放,但不重複,全開可拿齊);null = 未確認或不適用 | true |
| 排行榜 | 個人排行榜 / 家族排行榜 各有「有」「獎勵」兩個欄位;未經遊戲內截圖確認一律 null,確認後才寫 true/false | {"個人排行榜":{"有":true,"獎勵":null},"家族排行榜":{"有":false,"獎勵":false}} |
| 每日積分獎勵 | 僅杏林春魁:每個階段(每天)達到 100/300/500/1000 積分各領一次,五天相同;與排行獎勵分開 | {"說明":…,"門檻":[{"門檻":100,"獎勵":[…]}]} |
| 個人排行獎勵 / 家族排行獎勵 | 只有該排行榜「獎勵」確認為 true 時才出現;內容為名次區間與獎勵 | {"名次":[{"區間":"1","獎勵":[…]}]} |
| 備註 | 原圖附註、轉錄時的判斷 | [] |
| 表格 | 此資料夾內的獎勵表檔名,固定 | 獎勵.csv |

## 活動.json 後半段(階段)

`階段` 是一個陣列,每一階:

| 欄位 | 說明 |
|---|---|
| 階段 | 第幾階(1,2,3…) |
| 名稱 | 原圖的關卡名(1/10、海星、鏢師、第3場…) |
| 需求 | [{"項目":"積分","數量":30}];藥材類會有多個項目 |
| 累積 | 到此階的累積需求(無累積概念者為 null) |
| 獎勵 | [{"道具":"行動力","數量":20}];御貓疾行多一個 "名次" 欄 |
| 獎勵原文 | 原圖的文字,方便對照 |
| 輪數獎勵 | 只有御貓疾行有 |
| 項目 / 遊戲內說明 | 只有杏林春魁有:整理表的計分途徑、上限、建議囤貨;以及遊戲截圖的原文與單日積分上限 |

`額外獎勵`:階段之外的獎勵(完成大獎、救治大獎、靈感迸發、總共可領);有條件的會多一個 `需求` 欄。

## 獎勵.csv 欄位(每個活動相同)

| 欄位 | 說明 |
|---|---|
| 區塊 | 階段 / 額外獎勵 / 每日積分獎勵(每天相同) / 個人排行-階段獎勵(每日) / 個人排行-總獎勵(五天總積分) / 家族排行-… |
| 階段/名次 | 階段編號,或排行的名次區間 |
| 名稱 | 關卡名;御貓疾行會寫「第1場 第1名」 |
| 需求 | 該階需求(積分30、苦蔘根2、陳皮2…) |
| 累積 | 累積需求 |
| 獎勵 | 原圖文字 |
| 備註 | 御貓疾行的輪數獎勵等 |

## 91_養成(寵物 / 時裝 / 珍寶 / 珍藏 / 坐騎 / 裝備)
- 夥伴的養成在 99_養成參考,其餘五個系統在這裡,格式統一:`{說明, 區塊:[{標題, 說明, 表格 | 分組:[{標題,表格}]}]}`。
- 寵物:升級(N 20級 / R 40級 / SR 以上 60級)、升星(吃其他寵物)、覺醒。
- 時裝:升星範本(35 張,多套共用)。珍寶(守護):升級 / 突破 / 升星 / 隨機被動。
- 珍藏(收藏):升星(自己的碎片)/ 升級 / 羈絆。坐騎:每階的升級表,用行路補給。
- 裝備:強化(最高 300 級,消耗銀兩)、星級(寶石孔/升星材料/強化成長)、套裝加成、隨機詞條、裝備共鳴。
- 產生器:`工具/build_growth.py`。

## 名詞釐清:珍寶 vs 珍藏
- **珍寶** = 設定表的 `Guardian`(守護),34 件(玉佩、古琴、鶴鳴九皋…),可綁定夥伴,用「珍寶突破」升級。
- **珍藏** = 設定表的 `Collect`(收藏),40 件(金絲楠木籠、鏤心蝶玉…),有傳記故事與羈絆組合。
- 兩個是不同系統,各自有圖鑑頁與養成頁。

## 90_圖鑑(夥伴 / 寵物 / 時裝 / 珍寶 / 珍藏 / 坐騎 / 裝備 / 能力 / 貼紙集換 / 道具)
- 全部直接從遊戲設定表讀出來:夥伴 `Retinue`+`RetinueTie`+`FightSkill`+`Vocation`、
  時裝 `Dress`+`DressSuit`+`DressSuitTemplate`+`DressLabelDefine`+`DressBrand`、寵物 `Pet`(技能詞條另外抽)、道具 `ItemDefine`。
- 夥伴的突破上限、可覺醒、心途上限與 99_養成參考 是同一份資料;技能標的是「突破到第幾階解鎖」。
- 時裝:每件單品有五個風格標籤分數(活力/親和/知性/幹練/自信)與自己的屬性加成;整套可升星,
  每星十階、第9階要霓裳紗突破,每顆星解鎖一個星級效果。升星表是「範本」,多套時裝可能共用同一張。
  部位 4/5 的中文名(手持/配件、飾品)是依單品名稱推定,其餘欄位都照設定表。
- 寵物:同一種寵物有 N~UR 多個品質,資質範圍與技能詞條都不同;技能只列 1 級敘述(實際可升級)。
- 貼紙集換(畫冊):`CollectStickersAlbum`(126 本,reward 格式 `集滿張數#獎勵|…`)+ `PloyFixedRes`(貼紙名與主題,
  貼紙不在道具表、是集換系統自己的資源,所以遊戲介面常只顯示編號)。14 個主題名取自貼紙說明文字的【】。
  獎勵裡 18=時裝單品(`Dress`)、44=框飾類(`Frames`,big_page_name 就是台版分類名:頭像框/聊天氣泡/表情/工牌/天幕)、10=靈玉。
  抽卡的權重/保底/重複機率是伺服器算的,`Constants` 只有數字沒有品質對應,頁面上標了是推測。
  哪個主題開放由伺服器控制(同杏林春魁),設定表沒有日期。
- 屬性數值格式:`屬性id_來源_計算方式_數值`,計算方式 1 = 固定值、3 = 萬分比(率值屬性即使寫 1 也是萬分比)。
- 產生器:`工具/build_codex.py`。

## 圖片怎麼來的

- 正本在 `活動表格/圖庫/<類別>/<id>_<名稱>.png`,由 `工具/建圖庫.py` 產生;網頁讀的是
  `工具/做縮圖.py` 從圖庫產的 160px 縮圖(`活動表格/圖片/`)。每張圖的來源都記在 `圖庫/清單.csv`。
- **配圖只認設定表自己寫的 `icon` 字串**。icon 有前綴(`nengli_10012`、`huace_231`、`touxiang_60001`)
  就全樹搜,前綴本身夠唯一;icon 是純數字(道具 / 時裝 / 裝備)就限定在該系統自己的資源包裡找。
  配不到就留空,不用檔名數字去猜。
  > 之所以訂死這條:早期靠「檔名數字 == 設定表 id」當退路,結果把主線劇情背景 `br_10010.png`
  > 配成能力「春雨訣」、時裝 `10001.png` 配成「1級攻擊寶石」。同一個數字在 dress / buff / 家具 /
  > 劇情底下都有同名檔。
- 幾個沒有 icon 欄、要另外接的:夥伴頭像是 **`Retinue.source`** → `newheroicon/heroiconsmall/<source>.png`
  (不是 rid,也不是用名字接 NpcDefine);寵物是 `PetGuise.head`,用 `pet_type` 連回寵物。
- **圖不全是正常的**:圖是從裝置快取解包出來的,只有「被帳號持有或在畫面顯示過」的才會有檔。
  沒圖 ≠ 抽取失敗,而是五台帳號都還沒看過。例:坐騎 15 台只有 3 張,正好是帳號持有的那 3 台。

## 活動資料的來源
- 階段門檻、階段獎勵、時長、事件積分取自**遊戲解包出來的設定表**(`InsideTaskTime.lua` + `InsideJudgeTopic.lua`,工具/extract_activities.py)。
- 門檻仍以原圖轉錄為主並與設定表互相斷言(對不上產生器會失敗);獎勵內容則以設定表為準,原圖抄錯的地方已更正。
- 同一個活動在設定表裡有多個版本,採用與台版原圖門檻一致的那一版(對應 id 記在各活動的「資料來源」)。
- 設定表裡**沒有**的(這些是伺服器開活動時才下發,client 檔案查不到,只能靠原圖與實測):
  御貓疾行(RacingCat)的場次/名次獎勵、杏林春魁的每日積分獎勵與春魁榜名次獎勵、結算時間、是否補發獎勵、事件觸發次數上限。

## 99_養成參考 的資料來源
- 突破 / 覺醒 / 心途 / 升級的數值全部取自**遊戲解包出來的設定表**(client config),不是截圖推算。
- 原本由截圖與夥伴重置返還值推出來的值改成驗證用:SSR 突破表、覺醒表、心途七個重置檢查點、升級 210/220 級返還值,只要和設定表對不上,產生器就會直接失敗。

## 轉錄規則
- 「體」統一寫成「行動力」(依每日活動總覽的用法)。
- 事件名稱以遊戲內寫法為準並全檔統一:花籤占卜(原表有寫成「花籤轉盤」)、歷練大成功(原表有寫成「大成功」)、錦市裁衣(御貓疾行原圖寫成「錦事裁衣」)、霓裳券(珊瑚祕境原圖寫成「霓賞券」)。
- 總覽與活動分頁衝突時以分頁(活動原圖)為準,並在 00_總覽與規則 的「校對說明」寫明改了什麼;全拿數字由 build 時斷言比對,不一致會直接讓產生器失敗。
- 日晷的數量單位另放 `單位` 欄(分 / 小時)。
- 貼紙包顏色放在 `備註` 欄。
- 重複上傳的圖片用校驗碼比對後略過,不重複建檔。
